Topic: Connected to Wi-Fi but no internet access
Purpose: Basic IT support troubleshooting practice

1. UNDERSTAND THE ISSUE
- Ask the user what happens when they open a website.
- Confirm whether the issue affects one website or all websites.
- Check whether other devices can access the internet.

2. CHECK THE WI-FI CONNECTION
- Confirm that Wi-Fi is enabled.
- Confirm that the computer is connected to the expected Wi-Fi network.
- Check whether the issue continues.

3. CHECK NETWORK CONFIGURATION
- Use networksetup -getinfo Wi-Fi to inspect network information.
- Record the IP address, subnet mask and default router.
- Do not change network settings without understanding the cause.

4. TEST NETWORK CONNECTIVITY
- Use ping -c 4 1.1.1.1 to test external IP connectivity.
- Record whether packets are received or lost.
- Consider latency when reviewing the results.

5. TEST DNS RESOLUTION
- Use nslookup google.com to check whether the domain resolves.
- Record the returned IP address.
- If DNS resolution fails, investigate DNS configuration.

6. TEST WEBSITE ACCESS
- Use curl -I https://www.google.com to inspect the HTTP response.
- Record the response code.
- Remember that a successful test to Google does not prove that every website is working.

7. DOCUMENT THE RESULTS
- Record each test performed.
- Record the results and any error messages.
- Document the next troubleshooting action.

8. ESCALATION
- If the issue remains unresolved, escalate with the test results.
- Include the affected website URL and browser error.
- Do not close the ticket until the issue is resolved or properly handed over.

IMPORTANT
This guide is a personal training resource. Always follow the organisation's IT policies and approved troubleshooting procedures.

Topic: Connected to Wi-Fi but no internet access
Purpose: Basic IT support troubleshooting practice

1. UNDERSTAND THE ISSUE
- Ask the user what happens when they open a website.
- Confirm whether the issue affects one website or all websites.
- Check whether other devices can access the internet.

2. CHECK THE WI-FI CONNECTION
- Confirm that Wi-Fi is enabled.
- Confirm that the computer is connected to the expected Wi-Fi network.
- Check whether the issue continues.

3. CHECK NETWORK CONFIGURATION
- Use networksetup -getinfo Wi-Fi to inspect network information.
- Record the IP address, subnet mask and default router.
- Do not change network settings without understanding the cause.

4. TEST NETWORK CONNECTIVITY
- Use ping -c 4 1.1.1.1 to test external IP connectivity.
- Record whether packets are received or lost.
- Consider latency when reviewing the results.

5. TEST DNS RESOLUTION
- Use nslookup google.com to check whether the domain resolves.
- Record the returned IP address.
- If DNS resolution fails, investigate DNS configuration.

6. TEST WEBSITE ACCESS
- Use curl -I https://www.google.com to inspect the HTTP response.
- Record the response code.
- Remember that a successful test to Google does not prove that every website is working.

7. DOCUMENT THE RESULTS
- Record each test performed.
- Record the results and any error messages.
- Document the next troubleshooting action.

8. ESCALATION
- If the issue remains unresolved, escalate with the test results.
- Include the affected website URL and browser error.
- Do not close the ticket until the issue is resolved or properly handed over.

- Confirm whether the issue affects one website or all websites.
- Check whether other devices can access the internet.

2. CHECK THE WI-FI CONNECTION
- Confirm that Wi-Fi is enabled.
- Confirm that the computer is connected to the expected Wi-Fi network.
- Check whether the issue continues.

3. CHECK NETWORK CONFIGURATION
- Use networksetup -getinfo Wi-Fi to inspect network information.
- Record the IP address, subnet mask and default router.
- Do not change network settings without understanding the cause.

4. TEST NETWORK CONNECTIVITY
- Use ping -c 4 1.1.1.1 to test external IP connectivity.
- Record whether packets are received or lost.
- Consider latency when reviewing the results.

5. TEST DNS RESOLUTION
- Use nslookup google.com to check whether the domain resolves.
- Record the returned IP address.
- If DNS resolution fails, investigate DNS configuration.

6. TEST WEBSITE ACCESS
- Use curl -I https://www.google.com to inspect the HTTP response.
- Record the response code.
- Remember that a successful test to Google does not prove that every website is working.

7. DOCUMENT THE RESULTS
- Record each test performed.
- Record the results and any error messages.
- Document the next troubleshooting action.

8. ESCALATION
- If the issue remains unresolved, escalate with the test results.
- Include the affected website URL and browser error.
- Do not close the ticket until the issue is resolved or properly handed over.

Topic: Connected to Wi-Fi but no internet access
Purpose: Basic IT support troubleshooting practice

1. UNDERSTAND THE ISSUE
- Ask the user what happens when they open a website.
- Confirm whether the issue affects one website or all websites.
- Check whether other devices can access the internet.

2. CHECK THE WI-FI CONNECTION
- Confirm that Wi-Fi is enabled.
- Confirm that the computer is connected to the expected Wi-Fi network.
- Check whether the issue continues.

3. CHECK NETWORK CONFIGURATION
- Use networksetup -getinfo Wi-Fi to inspect network information.
- Record the IP address, subnet mask and default router.
- Do not change network settings without understanding the cause.

4. TEST NETWORK CONNECTIVITY
- Use ping -c 4 1.1.1.1 to test external IP connectivity.
- Record whether packets are received or lost.
- Consider latency when reviewing the results.

5. TEST DNS RESOLUTION
- Use nslookup google.com to check whether the domain resolves.
- Record the returned IP address.
- If DNS resolution fails, investigate DNS configuration.

6. TEST WEBSITE ACCESS
- Use curl -I https://www.google.com to inspect the HTTP response.
- Record the response code.
- Remember that a successful test to Google does not prove that every website is working.

7. DOCUMENT THE RESULTS
- Record each test performed.
- Record the results and any error messages.
- Document the next troubleshooting action.

8. ESCALATION
- If the issue remains unresolved, escalate with the test results.
- Include the affected website URL and browser error.
- Do not close the ticket until the issue is resolved or properly handed over.

IMPORTANT
This guide is a personal training resource. Always follow the organisation's IT policies and approved troubleshooting procedures.
